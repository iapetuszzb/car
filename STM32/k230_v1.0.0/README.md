# K230D + C06B + MS42C 单轴钢球平衡控制

这个版本按当前硬件资料从零创建。K230D 只负责检测钢球，并发送“钢球当前位置与屏幕中心的像素坐标差”；C06B 的 STM32F103 负责全部滤波、钢球速度估计、PD 控制、角度限制、转速限制、加速度限制和 STEP/DIR 脉冲输出。

核心目标：

- 屏幕中心对应像素误差 `0`；
- 不再按每帧误差累计相对步数；
- 每帧只更新一个“绝对目标角”；
- 正常控制角限制为 `±2.7°`；
- 在下述脉冲当量和启动零点假设成立时，软件命令硬边界严格小于 `±3°`；
- 默认最大电机速度不超过 `6°/s`；
- 默认最大电机加速度不超过 `30°/s²`；
- 中心附近使用位置和速度联合死区，抑制正反抖动；
- 单帧漏检时继续使用最后一次有效像素坐标；
- K230D 程序卡死、串口断开或完全停止发送后，C06B 在 150 ms 后平滑回到零位；
- 新的像素误差始终覆盖旧目标，不会排队追赶旧动作。

## 文件

- `k230d/pixel_error_sender.py`：K230D 使用的像素误差发送器。
- `k230d/integration_example.py`：复制进现有 CanMV 识球程序的集成示例。
- `c06b_controller/include/control_config.h`：所有需要确认或调节的参数。
- `c06b_controller/include/ball_controller.h`：中值滤波、位置/速度低通、死区迟滞和 PD 控制。
- `c06b_controller/src/main.cpp`：C06B UART 接收、硬件定时运动规划、STEP/DIR 输出和看门狗。
- `c06b_controller/platformio.ini`：STM32F103C8 PlatformIO 工程。
- `tests/`：协议和控制边界测试。

## 控制数据

K230D 每检测到一帧有效钢球，只发送一个有符号十进制整数和换行：

```text
-37
0
42
```

数值定义固定为：

```python
error_px = ball_center_x - screen_center_x
```

因此：

- 钢球在中心右侧：正数；
- 钢球在中心左侧：负数；
- 钢球位于中心：`0`；
- 某一帧没检测到钢球：重复发送最后一次有效数值；
- 上电后尚未有过任何有效识别：不发送；
- K230D 程序卡死或串口断开：自然停止发送，由 C06B 看门狗处理。

不能在漏检时发送假的 `0`。真实的 `0` 表示“确实看到了钢球，并且钢球位于中心”。`PixelErrorSender.ball_lost()` 会自动重复最后一次有效误差；只有 K230D 程序整体停止运行或通信真正中断时，C06B 才会在 150 ms 后超时回零。

在现有 K230D 识球循环中只需要：

```python
if ball_is_valid:
    error_px = ball_center_x - image_width // 2
    motor_sender.send(error_px)
else:
    motor_sender.ball_lost()  # 重发最近一次有效像素差
```

完整串口初始化参考 `k230d/integration_example.py`。其中 IO 11/12 只是示例，必须换成 K230D 板上实际空闲、并且接到 C06B 的引脚。

## 为什么这个版本比逐帧转动稳定

不稳定的典型写法是：

```text
本帧误差为 +20 -> 再向右移动若干步
下一帧仍为 +20 -> 又向右移动若干步
```

这样会持续累积相对动作。即使钢球位置已经改变，电机仍可能在执行旧队列，所以同时出现转幅过大、追赶旧目标、换向冲击和反应迟缓。

本版本改为：

```text
像素位置误差
  -> 3 帧中值滤波
  -> 位置低通
  -> 球速度低通
  -> PD 计算电机绝对目标角
  -> 目标角变化率限制
  -> ±2.7° 正常限位
  -> 定时器速度/加速度规划
  -> STEP/DIR
```

每个新误差只替换目标位置，不会追加一段旧运动。

## 默认角度与速度的严格计算

默认假设（关键是 MS42C 外部 STEP 输入的实际脉冲当量）：

```text
电机整步角：1.8°
整步数：200 step/rev
内部细分/电子齿轮假设：等效 16 细分
外部 STEP 输入脉冲数：3200 pulse/rev
每个微步：0.1125°
```

正常控制边界：

```text
floor(3200 × 2.7 / 360) = 24 pulse
24 × 360 / 3200 = 2.7000°
```

软件硬边界：

```text
floor(3200 × 3.0 / 360) = 26 pulse
26 × 360 / 3200 = 2.9250°
```

这里必须向下取整。16 细分时若错误地四舍五入成 27 pulse，实际会达到：

```text
27 × 360 / 3200 = 3.0375°
```

这会违反严格 `±3°` 的要求。

默认最大速度：

```text
floor(3200 × 6 / 360) = 53 pulse/s
53 × 360 / 3200 = 5.9625°/s
```

默认最大加速度：

```text
floor(3200 × 30 / 360) = 266 pulse/s²
266 × 360 / 3200 = 29.925°/s²
```

所有换算都故意向下取整，因此软件上限不会由于整数换算而超出配置值。

## C06B 引脚

根据当前工作区中的 C06B 原理图：

| 功能 | STM32 引脚 | C06B 接口 |
|---|---|---|
| K230 UART RX | PB11 | H3 蓝牙接口 |
| K230 UART TX | PB10 | H3 蓝牙接口 |
| STEP | PB6 | H4 舵机信号 |
| DIR | PB7 | H5 舵机信号 |
| EN（可选） | PB8 | H6 舵机信号 |
| USB 调试 RX/TX | PA10/PA9 | 板载 CH9102 |

建议逻辑映射如下；这不是允许 GPIO 直接连接电机端子的电气接线图：

```text
K230D UART TX  -> C06B PB11 / USART3 RX
K230D GND      -> C06B GND
C06B PB6 -> 经确认适配的电平/NPN/开集电极/光耦接口
          -> 经厂家资料确认的 MS42C STEP/PUL 端子
C06B PB7 -> 经确认适配的电气接口
          -> 经厂家资料确认的 MS42C DIR 端子
C06B PB8 -> 经确认适配的电气接口
          -> 经厂家资料确认的 MS42C EN 端子（最后才接）
```

### 重要电气限制

当前资料只有 MS42 板级原理图，没有 MS42C 外部连接器定义、光耦输入电压、STEP/DIR/EN 对应顺序、有效极性和最小脉宽。因此：

1. 不要仅凭本 README 直接把 3.3 V GPIO 接到 MS42C 端子。
2. 先用 MS42C 完整说明书或厂家资料确认 STEP、DIR、EN 和公共端。
3. 如果输入要求 NPN 下拉/开集电极，必须增加正确的三极管或光耦接口，不能把推挽 GPIO 当作 NPN 端子。
4. K230D 与 C06B 必须共地；电机功率电源不要从 K230D 取电。
5. `USE_MOTOR_ENABLE_PIN` 默认是 `0`，含义只是“C06B 不驱动 PB8/EN”，并不保证 MS42C 功率级处于禁用状态；驱动器在 EN 未接时是否默认使能仍需查厂家资料。
6. 只有同时确认 EN 端子、输入电压、公共端、接口方式和有效极性后，才能设置 `USE_MOTOR_ENABLE_PIN=1`；当前 `MOTOR_ENABLE_ACTIVE_HIGH=1` 只是待核对的占位值。
7. STEP 脉冲和 DIR 电平默认假设分别集中在 `MOTOR_STEP_ACTIVE_HIGH` 与 `MOTOR_DIRECTION_INVERTED`，也必须按实际接口核对。

## 上电零位

代码把上电时的电机位置定义为逻辑 `0°`。因此上电前必须：

1. 拆下钢球或固定钢球；
2. 人工把水管调到真实水平中位；
3. 再给 C06B/电机控制系统上电；
4. 只有人工确认机械机构已经静止且水管真实水平时，才可在 C06B USB 调试串口发送 `Z` 重新置零。代码只能检查内部规划速度，不能通过当前不可读的 MS42C 编码器验证真实静止。

如果在电机实际处于 `+2°` 时重启并错误地当成零点，软件允许的 `+3°` 相对运动可能让真实位置达到 `+5°`。因此，没有中位开关、绝对编码器位置或人工水平标定时，软件只能保证“相对启动零点”不超过 `±3°`。

MS42C 虽然内部带编码器，但当前资料没有其 UART/CAN 位置反馈协议，也没有把编码器 A/B 直接引出给 C06B。第一版依赖 MS42C 内部闭环保证它跟随 STEP 命令。若要对真实物理角度做独立的硬安全验证，还需要以下至少一种：

- 读取 MS42C 编码器实际角度的协议；
- 外接编码器到 C06B；
- 中位/正负限位开关；
- 可靠机械止挡。

## 编译与烧录 C06B

安装 PlatformIO 后：

```powershell
cd STM32\k230_v1.0.0\c06b_controller
pio run
pio run --target upload
pio device monitor --baud 115200
```

默认上传方式为 ST-Link。若 C06B 实际使用串口 Bootloader，需要根据现有烧录方式修改 `upload_protocol`。

当前版本已经使用 PlatformIO Core 6.1.19、ST STM32 platform 19.7.1 和 Arduino STM32 framework 2.12.0 完成固件编译。构建目标为 `genericSTM32F103C8`，实测占用约 `20036 / 65536 bytes Flash` 和 `1828 / 20480 bytes RAM`。烧录前仍需确认实际 C06B 芯片容量、Bootloader 和 `upload_protocol` 与该目标一致。

## 第一次安全调试顺序

不要一上来就放钢球闭环运行。建议严格按顺序进行：

1. 断开水管连杆或取下钢球。
2. 确认 MS42C 外部 STEP 输入确实为 `3200 pulse/rev`；同时核对电机整步角、内部细分和电子齿轮设置。
3. 若外部输入脉冲当量不是 3200 pulse/rev，先修改 `control_config.h`，不能只看内部细分标签。
4. 水管人工调平后上电。
5. K230D 连续发送 `0`，确认电机不动。
6. 手工发送约 `+20 px`，确认只产生很小的缓慢动作。
7. 若钢球会被该方向推得离中心更远，把 `kMotorPlantSign` 从 `+1` 改为 `-1`。
8. 分别持续发送大正误差和大负误差，确认 `current_steps` 永远在 `-24...+24` 正常范围内。
9. 确认调试输出的最大速度不超过 `53 step/s`。
10. 停止 K230D 发送，确认 150 ms 后目标平滑回零。
11. 最后才安装钢球，以较小 `Kp`、`Ki=0` 开始闭环。

## 调参

所有参数集中在 `c06b_controller/include/control_config.h`。

### 仍然抖动

按这个顺序处理：

1. 确认没有把驱动器设成 4 细分；推荐 16 或 32 细分。
2. 确认 K230 单帧漏检时调用 `ball_lost()` 重发最后坐标，而不是发送假 `0`。
3. 把 `kMaximumMotorSpeedMilliDegS` 从 `6000` 降到 `4000`。
4. 把 `kMaximumMotorAccelerationMilliDegS2` 从 `30000` 降到 `20000`。
5. 把 `kKpDegPerNormalizedError` 从 `1.80` 降到 `1.30`。
6. 若过中心后反复摆动，逐步提高 `kKdDegPerNormalizedVelocity`，例如 `0.45 -> 0.55 -> 0.65`。
7. 若检测坐标静止时本身跳动超过 3 px，提高中心进入/退出阈值。
8. 检查连杆间隙、齿条回差、管道松动和驱动电流。

### 回中心太弱

1. 保持 `Ki=0`；
2. 小步提高 `Kp`，每次约 `0.1~0.2`；
3. 如果电机速度明显跟不上球，而目标角经常撞到 `±2.7°`，先把最大速度从 `6°/s` 提到 `8°/s`，不要直接大幅提高 `Kp`；
4. 最大速度仍应由定时器层严格限制。

### 存在长期固定偏差

先检查机械水平零位。只有机械零位正确但仍有长期小偏差时，才把 `Ki` 从 `0` 调到很小的值，例如 `0.02`，并保持积分最大只贡献 `±0.25°`。积分过大是球杆系统低频摆动的常见原因。

## 参考的开源实现

控制结构参考了以下项目，但本仓库代码为针对当前系统重新编写，没有直接复制其受限制许可代码：

- [gin66/FastAccelStepper](https://github.com/gin66/FastAccelStepper)：绝对目标、非阻塞脉冲、严格速度/加速度、新目标覆盖旧目标。
- [makerbase-mks/MKS-SERVO42B](https://github.com/makerbase-mks/MKS-SERVO42B)：STM32 固定周期控制、编码器闭环步进结构和安全限幅思路。
- [JohanLink/Ball-Balancing-PID-System](https://github.com/JohanLink/Ball-Balancing-PID-System)：视觉位置与球速度反馈、丢球处理；该项目是二维平台且许可带非商业限制，所以只参考思想。
- [giusenso/Ball-Balancing-PID-System](https://github.com/giusenso/Ball-Balancing-PID-System)：速度滑动平均、积分限幅、每周期输出变化限制。
- [pkinney/ballbeam](https://github.com/pkinney/ballbeam) 和 [pkinney/pid_control](https://github.com/pkinney/pid_control)：真正的一维 ball-and-beam、真实 `dt`、D 项低通和 anti-windup。

## 当前仍需确认的硬件参数

代码已经完整实现控制逻辑和安全边界，但以下信息无法从当前工作区恢复，必须在第一次接线/烧录前核对：

- MS42C 的完整外部端子定义；
- STEP/DIR/EN 输入电压、公共端、接口方式和有效极性；
- 电机实际整步角、MS42C 外部 STEP 输入脉冲当量/电子齿轮，以及内部细分；
- STEP 最小高低电平宽度；
- C06B 是否就是 K230D 与 MS42C 之间实际使用的控制板；
- 电机正方向与钢球像素正方向的对应关系；
- 启动时真实水平中位的建立方法。

这些参数中，任何一个错误都可能导致方向相反、角度换算错误或损坏接口。控制代码已经把它们集中在一个配置文件中，确认后无需改动核心算法。
